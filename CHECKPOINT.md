# Текущая контрольная точка

## Завершённая задача

TASK-007 — чистый фиктивный source adapter без нормализации.
Задача выполнена в ветке `task/007-fixture-source-adapter` и слита в `main`
отдельным merge-коммитом.

## Состояние основной ветки

- TASK-001, TASK-002, TASK-003, TASK-004, TASK-005, TASK-006 и TASK-007 слиты
  отдельными merge-коммитами.
- Короткоживущая ветка TASK-007 сохраняет исходный атомарный содержательный
  коммит в истории после безопасной интеграции в `main`.
- Удалённый репозиторий не настроен и не требуется в текущем объёме.

Текущий SHA, активную ветку, факт интеграции и чистоту дерева следует подтверждать
через Git, поскольку документ не дублирует изменяемые идентификаторы истории.

## Что уже существует

- Локальный Git-репозиторий, проектные правила и переносимые документы состояния.
- CPython `>=3.14,<3.15`, `.python-version` для 3.14.7, `uv`, `pyproject.toml`,
  зафиксированный `uv.lock` и устанавливаемый `src`-пакет
  `real_estate_parser`.
- Pydantic 2.x как единственная runtime-зависимость; pytest, Ruff и mypy как
  development-зависимости.
- Переносимая команда `uv run quality`: Ruff format-check, Ruff lint, строгий
  mypy, smoke pytest и отдельный pytest-этап fixture integrity.
- Офлайн-проверки всех manifest-связей, JSON-синтаксиса, UTF-8 без BOM и
  канонических byte-exact `expected/search-*.json`.
- Публичная строгая граница `load_fixture_source_batch(Path)` для чтения одного
  локального UTF-8 JSON и проверки `fixture-source-batch@1`.
- Нейтральные immutable-типы `InputLocation`, provided/missing source fields,
  `ValidatedSourceListing`, `ValidatedSourceBatch`, `ContractIssue` и атомарный
  типизированный результат без зависимости от Pydantic, JSON и filesystem.
- Стабильное собственное отображение syntax/schema ошибок, структурные
  locations, независимая сортировка и точное совпадение multi-error fixture с
  diagnostic oracle.
- Immutable-типы `SourceId`, `PublicationId`, `PublicationRef`, `RawField`,
  `MissingField`, `SourcePublicationSnapshot`, `SourceBatch` и атомарного
  результата фиктивной адаптации.
- Чистая публичная операция `adapt_fixture_source_batch(ValidatedSourceBatch)`,
  которая назначает `fixture_portal`, проверяет publication id и точный исходный
  HTTPS URL и переносит строки и locations без нормализации.
- Прямые unit-тесты адаптера без JSON/Pydantic/filesystem и один offline
  интеграционный тест существующего loader с адаптером.
- Проект первого локального среза: JSON-фикстура → строгая валидация → фиктивный
  адаптер → нормализация → атомарная коллекция → стандартный поиск →
  детерминированный JSON.
- Предметная идентичность, канонические типы, происхождение каждого значения,
  `Present`/`Missing`/`Unsupported`, стабильные ошибки, поиск и сортировка TASK-003.
- Точные внешние документы `fixture-source-batch@1` и `search-criteria@1`,
  версионированный каталог `tests/fixtures/v1`, негативная матрица и byte-exact
  oracle TASK-004.

## Что намеренно не реализовано

- Нормализованные Python-типы, `Provenance`, состояния `Present`/`Unsupported`,
  Pydantic-модели критериев и результата.
- Нормализация, коллекция, поиск, mapper и сериализатор результата.
- Пользовательский CLI первого среза.
- Несколько наблюдений, постоянное хранилище, история изменений и дедупликация.
- Физический объект недвижимости, база данных, API, HTTP, HTML и реальные
  площадки.
- Нестандартные сигналы, ИИ, уведомления, UI, OpenClaw и Telegram.
- Docker, CI, развёртывание, удалённый репозиторий и динамический загрузчик
  плагинов.

## Рекомендуемая следующая задача

**TASK-008 — детерминированная нормализация одного снимка.** Принять один
`SourcePublicationSnapshot` и вернуть `NormalizedListing` либо упорядоченные
ошибки `NORMALIZATION`: выполнить exact parsing времени, location whitespace,
цены/валюты, площади и комнат, сформировать полное происхождение и состояния
`Present`/`Missing`/`Unsupported`. Не начинать атомарную коллекцию, duplicate
detection, поиск, output mapping, CLI или реальные площадки.
