# TASK-005 — программный каркас и единая команда качества

- Статус: завершено
- Рабочая ветка: `task/005-program-scaffold-quality`
- Целевая ветка: `main`

## Цель

Создать минимальный устанавливаемый Python-каркас и одну переносимую команду,
которая воспроизводимо проверяет весь текущий репозиторий, не начиная реализацию
предметного потока первого среза.

## Включённый объём

- CPython `>=3.14,<3.15`, `uv`, `pyproject.toml`, `uv.lock` и `src`-layout.
- Pydantic 2.x как единственная runtime-зависимость; pytest, Ruff и mypy как
  development-зависимости.
- Минимальный устанавливаемый пакет `real_estate_parser` и smoke test импорта.
- Переносимый технический console-script `uv run quality`.
- Ruff format-check, Ruff lint, строгий mypy, pytest и отдельный этап проверки
  целостности `tests/fixtures/v1`.
- Проверка JSON-синтаксиса, manifest-связей, UTF-8 без BOM и канонических байтов
  `expected/search-*.json`.
- Обновление документации и контрольной точки проекта.

## Исключённый объём

- Предметные сущности и Pydantic-контракты объявлений или критериев.
- Контракт и адаптер источника, нормализация, коллекция, поиск и output mapping.
- Пользовательский CLI первого среза, API, хранилище и реальные площадки.
- HTTP, HTML, браузерная автоматизация, ORM, БД, AI SDK и CLI-фреймворки.
- OpenClaw, Telegram, Docker, CI, развёртывание и динамические плагины.
- Автоматическое форматирование из `quality`, исправление fixtures, обновление
  golden-файлов или lock-файла.

## Решения задачи

- Версия Python для локального окружения закреплена в `.python-version` как
  `3.14.7`, а поддерживаемый диапазон проекта остаётся `>=3.14,<3.15`.
- Для установки `src`-пакета и регистрации console-script применён минимальный
  официальный backend `uv_build`; он не является runtime- или dev-зависимостью
  приложения.
- `quality` реализован обычным Python entry point. Он запускает каждый этап из
  корня проекта, останавливается при первом сбое, показывает имя этапа и
  возвращает ненулевой код.
- Общие тесты и fixture integrity разделены на два явно названных pytest-этапа,
  чтобы каталог v1 оставался самостоятельной проверяемой границей.
- Проверка fixtures читает только статические локальные файлы, сортирует пути и
  не использует сеть, часы, случайность, locale или порядок файловой системы.
- Нового долгосрочного архитектурного решения задача не вводит, поэтому ADR не
  создавался.

- [x] `uv run quality` последовательно запускает все пять заявленных этапов.
