# 0002. Первый локальный сквозной срез

- Статус: принято
- Дата: 2026-08-31
- Задача: TASK-002

## Контекст

Первый исполняемый результат должен проверить направление зависимостей и взаимодействие источника, нормализации и поиска, не смешивая это с сетью, площадкой, хранилищем или интерфейсом. Срез обязан быть достаточно малым для одной короткой задачи и достаточно полным, чтобы его результат можно было проверить снаружи.

## Рассмотренные варианты

### Сразу реальный сайт

Отклонено: добавляет правовые ограничения, сетевую нестабильность, защиту площадки и особенности HTML до проверки внутренних контрактов.

### Сразу API и база данных

Отклонено: проверяет инфраструктуру раньше предметного потока и заставляет принять решения о хранении и веб-фреймворке без сформулированной нагрузки.

### Локальная JSON-фикстура и CLI

Принято: даёт воспроизводимый недоверенный вход, внешний исполняемый интерфейс и машиночитаемый результат при минимуме зависимостей. CLI является входным адаптером и не влияет на ядро.

## Решение

Первый срез читает два локальных JSON-файла: набор вымышленных сырых объявлений одного фиктивного источника и критерии стандартного поиска. Затем приложение:

1. строго проверяет структуры и сообщает ошибки с привязкой к записи и полю;
2. через адаптер фиктивного источника создаёт нейтральные входные записи;
3. нормализует только минимальные поля, необходимые критериям;
4. сохраняет происхождение каждого показанного нормализованного значения;
5. держит данные только в памяти процесса;
6. применяет стандартные фильтры без дедупликации и вероятностных сигналов;
7. сортирует совпадения детерминированно;
8. выводит JSON-результат в стандартный поток, а ошибки — отдельно с ненулевым кодом завершения.

Подробный контракт поведения находится в `docs/design/FIRST-VERTICAL-SLICE.md`. Физические типы и интерфейсы проектируются в TASK-003, стратегия фикстур и полный набор проверок — в TASK-004.

## Последствия

- Сквозной поток можно повторять без сети и внешних сервисов.
- Одни и те же прикладные операции позднее смогут вызываться из API, Telegram или OpenClaw через другие адаптеры.
- Срез не доказывает пригодность конкретного сайта, базы данных или алгоритма дедупликации.
- Добавление реального источника потребует отдельного исследования его правил и отдельного адаптера.

## Проверка и условия пересмотра

Решение считается подтверждённым, когда реализация с нуля устанавливается через lock-файл, все проверки проходят, валидная фикстура даёт стабильный результат с происхождением, а невалидная отклоняется без частичного успеха. Срез пересматривается до реализации только если TASK-003 обнаружит, что минимальное происхождение невозможно выразить без дополнительной границы.
