# 0011. Контракт ограниченного read-only пилота ЦИАН

- Статус: принято
- Дата: 2026-09-02
- Задача: TASK-028
- Решение о пилоте: `CONDITIONAL_GO`

## Контекст

После TASK-027 проект имеет только нейтральные source/domain/persistence
контракты и fully fictional fixtures. Перед первым обращением к реальной
площадке необходимо отдельно доказать допустимый способ доступа, назначение
доступа, предел запросов, минимальный состав данных, правила персональных
данных, retention и stop conditions. Отсутствие опубликованного запрета не
является разрешением, а техническая доступность интерфейса не является правом
его использовать.

Пользователь выбрал ЦИАН и отдельно разрешил сетевое исследование официальных
источников. В рамках исследования 2026-09-02 не открывались страницы поиска и
карточки объявлений, не вызывались data endpoints и не сохранялись реальные
данные.

Актуальные публичные документы ЦИАН устанавливают одновременно:

- правила сайта, пункты 7.2.3, 7.2.5 и 7.2.7, запрещают неразрешённые
  автоматизированные скрипты, доступ вне предоставленных интерфейсов и
  несогласованное извлечение материалов базы;
- условия API, пункты 1.1–1.2 и 3.5, требуют получить ключ у ЦИАН и отдельно
  запрещают автоматизированный сбор через API без предварительного разрешения;
- опубликованный OpenAPI catalog описывает получение объявлений агентства,
  деталей объявлений агентства и отчётов о входящем XML-импорте, но не метод
  поиска/получения публичных объявлений третьих лиц для внешнего поискового
  продукта;
- документация рекомендует не более 10 запросов в секунду на метод, но прямо
  предупреждает, что для отдельных методов предел зависит от передаваемого
  контента. Это рекомендация общего уровня, а не достаточная документированная
  квота для отсутствующего public-listings метода.

Лицензионное соглашение в пункте 4.1.3 допускает определённое извлечение данных
об объектах с указанием базы ЦИАН, но пункты 4.1.5, 4.2.4 и 8.1.1–8.1.3 вместе
с более специальными правилами сайта/API не дают самостоятельного разрешения
на автоматизированный внешний поисковый сбор. Это архитектурное решение не
является юридическим заключением; противоречие или пробел трактуется как
блокирующее условие.

## Рассмотренные варианты

### Официальный API или договорной партнёрский доступ

Использовать только endpoint/feed, который ЦИАН официально документировал и
письменно разрешил именно для bounded read-only получения публичных объявлений
третьих лиц внешним поисковым прототипом. Разрешение обязано охватывать поля,
назначение, хранение, производные преобразования, атрибуцию, срок и квоты.

Преимущества — проверяемое основание, стабильная схема, явные ограничения и
возможность воспроизводимого аудита. Недостаток — текущий опубликованный API не
содержит нужного public catalog метода; одного API-ключа недостаточно.

### HTML/browser scraping

Получать поисковую выдачу или карточки через HTML, browser automation либо
внутренние site endpoints. Даже если `robots.txt` содержит `Allow` для
отдельного внутреннего пути, этот путь не включён в опубликованный public API,
а правила 7.2.3/7.2.5/7.2.7 требуют разрешения и предоставленного интерфейса.
`robots.txt` управляет crawler behavior, но не заменяет согласование условий.

Преимущество только техническое — видимость данных в браузере. Недостатки —
прямой конфликт с условиями, CAPTCHA/блокировки, нестабильная схема и риск
получения контактов, текста и изображений. Вариант отвергнут.

### Разрешённый внешний XML/feed

Принимать исходящий feed ЦИАН или партнёра только по отдельному письменному
соглашению, которое разрешает использование публичных объявлений в этом
поисковом продукте. Публичная документация ЦИАН упоминает XML как входящий
источник объявлений агентства в базу ЦИАН и предоставляет отчёты об импорте;
это не исходящий public-listings feed и не разрешение на повторное
использование каталога.

Преимущество будущего договорного feed — bounded server-provided dataset без
HTML. Недостаток текущего состояния — подходящий feed и его условия не
опубликованы. Вариант допустим только после отдельного договора/разрешения.

## Решение

Принят статус **`CONDITIONAL_GO`**.

Это означает:

- controlled live pilot сейчас **запрещён**;
- HTML scraping, browser automation, reverse-engineered и иные
  недокументированные endpoints имеют постоянный `NO_GO` в рамках этого ADR;
- опубликованные `get-my-offers`/`get-my-offers-detail` и XML import reports не
  подходят для поиска публичных объявлений третьих лиц;
- API-ключ без отдельного предварительного разрешения на указанный use case не
  разблокирует пилот;
- единственный допустимый будущий режим — официальный documented API либо
  договорной исходящий feed с явным письменным разрешением ЦИАН на bounded
  read-only public-listings pilot;
- общий совет «не более 10 запросов/с на метод» фиксируется как опубликованная
  рекомендация, но не используется как разрешённый лимит будущего метода.
  До получения method/feed-specific ceiling, quota window и retry behavior
  live pilot запрещён.

Полный набор обязательных доказательств, минимальный traffic/data budget,
PII/retention rules, stop conditions и audit receipt заданы в
[детальной спецификации](../design/CIAN-READ-ONLY-PILOT-CONTRACT.md).

## Последствия

- TASK-028 не создаёт source adapter, scraper, fixture, schema, account или
  API-key и не обращается к объявлениям.
- Нельзя молча использовать внутренний path, обнаруженный в `robots.txt`,
  HTML/GraphQL/XHR браузера, cookies, proxy, CAPTCHA solving или иной обход.
- Следующий практический шаг — получить от уполномоченного представителя ЦИАН
  письменное подтверждение use case, интерфейса, полей, retention и квот, а
  также provider-supplied synthetic/redacted либо явно разрешённый sample.
  TASK-028 не отправляет такое обращение.
- Только после снятия всех blockers отдельная TASK-029 может реализовать
  **offline** adapter на сохранённом разрешённом примере без live access.
- Controlled live pilot остаётся ещё более поздней отдельной задачей и требует
  повторной проверки документов непосредственно перед запуском.
- Existing domain contracts, persistence ports и fully fictional fixture
  policy не изменяются.

## Проверка и условия пересмотра

`CONDITIONAL_GO` может перейти в executable pilot gate только если одновременно
получены и сохранены как audit evidence:

1. письменное разрешение ЦИАН именно на автоматизированное read-only получение
   публичных объявлений третьих лиц для внешнего поискового прототипа;
2. официальный documented endpoint либо исходящий partner feed без
   reverse engineering;
3. явные права на заявленные поля, кратковременное хранение, нормализацию,
   offline testing и атрибуцию;
4. method/feed-specific rate ceiling, quota window, pagination/record cap и
   retry rule;
5. schema/field contract, позволяющий исключить контакты, account identifiers,
   свободный текст и изображения;
6. согласованный retention/deletion срок и разрешённый sample для TASK-029;
7. повторная проверка актуальных site/API terms, API schema и `robots.txt` без
   конфликта с разрешённым route.

Если ЦИАН отказывает, ограничивает доступ собственными объявлениями либо не
даёт однозначного ответа хотя бы по одному пункту, результат становится
`NO_GO` для ЦИАН и проект выбирает другой источник отдельной задачей. Новый
ADR нужен для смены режима доступа, расширения полей/retention, свободного
текста, изображений, browser automation или ослабления stop conditions.
