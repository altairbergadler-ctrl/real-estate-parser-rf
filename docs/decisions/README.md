# Архитектурные решения

Этот каталог хранит существенные решения, которые меняют архитектурные границы, модель данных, направление зависимостей, технологическую основу или важные эксплуатационные свойства.

## Когда создавать запись

Запись нужна, если решение:

- трудно или дорого отменить;
- влияет более чем на одну задачу или модуль;
- выбирает один значимый вариант вместо других;
- уточняет или изменяет принципы `ARCHITECTURE.md`.

Мелкие локальные детали реализации не требуют отдельного документа.

## Именование и формат

Используется имя `NNNN-краткое-название.md`, где номер растёт последовательно. Рекомендуемая структура:

```markdown
# NNNN. Название решения

- Статус: предложено | принято | заменено
- Дата: ГГГГ-ММ-ДД
- Задача: TASK-NNN

## Контекст
## Рассмотренные варианты
## Решение
## Последствия
## Проверка и условия пересмотра
```

Принятое решение не переписывается задним числом. Если направление меняется, создаётся новая запись, которая ссылается на заменённую.
